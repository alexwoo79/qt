# 第一阶段例题讲解（第 1–2 周：内存地基）

> 5 道例题，每题都能直接跑：`clang++ -std=c++17 -g -O0 code/p1_0X_*.cpp -o /tmp/demo && /tmp/demo`
> 下面每段"真实输出"都是在本机（Apple clang 21 / arm64）跑出来的。**地址每次运行都不同**，看的是相对关系，不是具体数值。

## 例题 1-1 空类与基础类型：sizeof 到底在说什么

**目标**：能先预测再验证——一个类型占多少字节，跟"它有几个成员"不是同一件事。

**代码**：`code/p1_01_sizeof.cpp`

```cpp
struct Empty {};                    // 空类：编译器必须给 1 字节占位
struct OneChar { char c; };
struct CharInt { char c; int i; };  // 1 + 3 填充 + 4 = 8
struct IntChar { int i; char c; };  // 4 + 1 + 3 尾部填充 = 8
struct HasFunction { void f(); };   // 非虚成员函数不占对象内存
struct HasVirtual { virtual void f(); };
```

**真实输出**

```text
sizeof(Empty)        = 1
sizeof(OneChar)      = 1
sizeof(CharInt)      = 8   (char 后补 3 字节)
sizeof(IntChar)      = 8   (尾部再补 3 字节)
sizeof(HasFunction)  = 1   (成员函数不占对象内存)
sizeof(HasVirtual)   = 8   (只有一个 vptr)
-- 基础类型（64 位平台）--
bool=1 char=1 short=2 int=4 long=8 long long=8
float=4 double=8 long double=8
int*=8 void*=8 函数指针=8
两个空类对象：0x16ee2e47b 与 0x16ee2e47a，相差 -1 字节
```

**讲解**

1. `Empty` 是 1 而不是 0——因为 C++ 要求**每个对象都有唯一地址**，编译器只能塞一个字节占位。
2. 两个空类对象地址相差 **-1**：栈向低地址增长，`b` 建在 `a` 的下方，正好各自 1 字节。
3. `CharInt`：`char` 在偏移 0，`int` 必须 4 字节对齐，所以中间补 3 字节，总 8。
4. `IntChar`：`int` 在 0，`char` 在 4，结构体整体按最大成员（4）对齐，尾部再补 3，还是 8。
5. `HasFunction` = 1：**成员函数不在对象里**，它们编译成普通函数，调用时额外传 `this`。
6. `HasVirtual` = 8：一旦有虚函数，对象里多出一个 vptr（例题 1-4 展开）。

**动手改一改**：加一个 `struct LongDouble { char c; long double ld; };`，先预测再跑（本机 `long double` 是 8 字节，对齐 16，结果是 16）。

**常见误区**：把 `sizeof` 当"实际用掉的内存"。它只是**类型合同**：数组步长、`memcpy` 长度、指针算术都以它为准。

**Rust 对照**：Rust 的空结构 `struct Empty;` 也是 1 字节（ZST 只在独立存在时被优化），`#[repr(C)]` 才强制和 C 一样的布局；默认布局是编译器自由安排的——这点 C++ 反而更"可预测"。

**验收问题**：为什么 `{ double d; char c; }` 是 16 而不是 9？

## 例题 1-2 成员顺序与内存布局：offsetof + 字节 dump

**目标**：能看着字节流指出"这是哪个成员、哪几个字节是填充"。

**代码**：`code/p1_02_layout.cpp`（关键部分）

```cpp
struct LooseLayout { char c; double d; int i; };   // 24 字节
struct TightLayout { double d; int i; char c; };   // 16 字节
template <typename T> void dump_bytes(const T& obj, const char* name);  // 逐字节打印
```

**真实输出**

```text
sizeof(LooseLayout) = 24
  offsetof c=0 d=8 i=16
sizeof(TightLayout) = 16
  offsetof d=0 i=8 c=12
同样的三个成员，顺序不同差了 8 字节。
LooseLayout  (24 字节): aa 00 00 00 00 00 00 00 00 00 00 00 00 00 f0 3f 44 33 22 11 00 00 00 00
TightLayout  (16 字节): 00 00 00 00 00 00 f0 3f 44 33 22 11 aa 00 00 00
sizeof(std::string) = 24（libc++ 固定 24 字节）
sizeof(WithString)  = 40  offsetof(s)=8 offsetof(c)=32
```

**讲解**

1. `LooseLayout` 里 `char` 占 0，`double` 要 8 对齐 → 偏移 8，那 7 个 `00` 就是填充；`int` 落在 16，尾部再补 4 → 24。
2. `TightLayout` 先放 8 字节的 `double`，再 `int`(8)、`char`(12)，尾部补 3 → 16。**同样的字段省了 8 字节**。
3. 字节流里能直接认出来：`f0 3f` 是 `double 1.0` 的高位，`44 33 22 11` 是 `0x11223344`（小端：低字节在前）。
4. `std::string` 本体固定 24 字节（libc++）：指针/长度/容量或 SSO 缓冲都在里面——**字符串数据不一定在堆上**，这是例题 2-1 的伏笔。

**动手改一改**：加 `struct Mixed { char a; int b; char c; double d; };`，先算再验（本机是 24）。

**常见误区**：以为"成员按声明顺序紧密排列"。真实规则是**按对齐要求排布 + 必要时插入填充**，声明顺序只保证"偏移不减"。

**Rust 对照**：Rust 默认会重排字段以降内存（`repr(Rust)`）；想固定 `repr(C)`。C++ 不重排，所以**手动排序是 C++ 程序员的基本功**。

**验收问题**：`{ char c; int i; char c2; }` 是几字节？填充分别在哪？

## 例题 1-3 栈与堆：地址方向、生命周期、谁负责释放

**目标**：把"栈自动、堆手动"从口号变成看得见的地址变化。

**代码**：`code/p1_03_stack_heap.cpp`（递归打印局部变量地址；循环 `new Node`）

**真实输出（节选）**

```text
-- 栈：向低地址方向增长 --
level(0): 栈变量 &local = 0x16b4de3c8
level(1): 栈变量 &local = 0x16b4de398
level(2): 栈变量 &local = 0x16b4de368
level(3): 栈变量 &local = 0x16b4de338
g_counter（全局/静态区）地址 = 0x104928000
arr[0] 值=0 地址=0x16b4de450（同一数组内连续，步长 4）
arr[1] 值=1 地址=0x16b4de454
-- 堆 --
new Node{value=0} → 堆地址 0x104955500
new Node{value=1} → 堆地址 0x104955510
头指针 head 本身在栈上：&head=0x16b4de430（8 字节），指向堆上的节点
作用域内的 scoped 在 0x16b4de41c
作用域外的 reused 在 0x16b4de418（地址常被复用）
delete 堆节点 0x104955520（值 2）…
```

**讲解**

1. 四层递归的 `&local` 每层减 0x30：**栈向下长**，每层的栈帧大小固定。
2. 全局变量在 `0x104928000` 附近，和栈（`0x16b4…`）差着几个数量级——**栈、堆、全局是三个不同的地址区间**。
3. 同一数组内地址连续且步长恰好 4（`sizeof(int)`）；而三个独立局部变量 `a/b/c` **不保证连续**。
4. 堆地址按 16 字节间隔增长（分配器对齐）——注意：**这不是语言保证**，只是当前分配器的行为。
5. `scoped` 与 `reused` 地址几乎相同：栈帧回收后空间被复用。这就是"野指针很危险"的物理基础——地址看着对，内容已经变了。

**动手改一改**：把 `level()` 加上一个 `char buf[64]`，看每层地址差值变成多少，验证"栈帧大小 = 局部变量总和（对齐后）"。

**常见误区**：以为"局部变量地址按声明顺序递减"。真实情况由编译器决定，别依赖。

**Rust 对照**：Rust 默认值语义 + 所有权，栈上对象随作用域自动析构（同 RAII）；堆要用 `Box`，且没有裸 `new/delete`——**所有权写在类型里**。

**验收问题**：为什么 `&a`、`&b`、`&c` 不保证连续，而 `&arr[0]`、`&arr[1]` 必须连续？

**内存结构图**：`memory-maps/p1_03_memory_map.pdf`（脚本 `draw_p1_03.py`，3 页）——

1. 第 1 页把**栈 / 堆 / 静态区**三段区间画在同一张图上：`level(0..3)` 四层栈帧（每层 `-0x30`）、
   `new Node` 出来的三块堆（含 `head` 指针跨区指向）、`g_counter` 所在的静态区，并标出三者相差几个数量级。
2. 第 2 页把 **main 的栈帧按 4 字节一格格出来**：`arr[0..3]` 紧挨着、`a/b/c` 顺序由编译器定、
   `head` 占两格（8 字节指针）、`scoped`/`reused` 挤在同一块位置。
3. 第 3 页画 **Node 的 16 字节**（`value` 4 + 填充 4 + `next` 8，附原始字节 dump）、分配 → 链表 →
   释放的顺序，以及一张「栈 vs 堆」对照表。

画图时顺手做了一次跨平台复核（`memory-maps/probe_p1_03.cpp`，Linux x86-64 / GCC 16.2），
补上三条本机事实：

- 四层递归每层同样差 **0x30**，加一个 `char buf[64]` 后变成 **0x70**（112 字节）——
  「栈帧大小 = 局部变量之和（对齐后）」在两端都成立。
- 同一次运行里 **第 3 次 `new` 落到了更低的地址**（`0x100eada10` < `0x100eadbb0`）：
  堆连"间隔固定"都不成立，更别说顺序 —— 它是分配器的当下行为，不是语言保证。
- `scoped` / `reused` 在本机 GCC 上地址**完全相同**（存档的 clang 是相邻 4 字节）：
  地址复用不是巧合，是规则。

## 例题 1-4 虚函数如何改变对象：vptr 与虚表

**目标**：亲眼看到"对象里那 8 字节"怎么指向一张全局表，并绕过语法直接按表调用。

**代码**：`code/p1_04_vptr.cpp`（把对象首 8 字节当 `void**`，再当函数指针数组）

**真实输出**

```text
sizeof(Plain)       = 4（int + 填充）
sizeof(WithVirtual) = 16（int 4 + 填充 4 + vptr 8）
sizeof(Derived)     = 16（没加成员，只是换掉表里的函数）
WithVirtual     vptr=0x104e58010
    vtable[0] = 0x104e547ec
    vtable[1] = 0x104e54814
WithVirtual#2   vptr=0x104e58010      ← 同类对象共用一张表
Derived         vptr=0x104e58040
    vtable[0] = 0x104e54888           ← 重写后槽位换成新函数
    vtable[1] = 0x104e54814           ← 没重写的槽位保持原样
对象前 8 字节的原始值（就是 vptr）：1080e50401000000
-- 绕过语法，直接按虚表调用 --
WithVirtual::f()
WithVirtual::g(42)
```

**讲解**

1. `sizeof(Plain)` 是 4：只有 `int`（4 字节已对齐）。`WithVirtual` 变成 16：vptr 8 字节 + `int` 4 + 填充 4。
2. `WithVirtual` 与 `WithVirtual#2` 两个对象的 vptr **完全相同**——虚表是"每类一张"，对象只存一个指针。
3. `Derived` 没加任何成员，sizeof 不变，但 vptr 指向**另一张表**：`f` 被换成 `Derived::f`，`g` 原样保留。
4. 对象前 8 字节的十六进制 `1080e50401000000` 就是那个 vptr 的小端表示（低地址在前）。
5. 最后两行最关键：`f0(&base)` 是**手写的虚调用**——我们只是照着表里的地址跳过去，和编译器生成的多态调用是同一件事。

**动手改一改**：给 `Derived` 加 `virtual void h()`，重新打印 `vtable[0..2]`，验证"新增虚函数是追加到表尾"。

**常见误区**：以为"虚表跟着对象走"。虚表在只读数据段，对象里只有一个指针——所以对象变大 8 字节，不是"每个对象一张表"。

**Rust 对照**：Rust 的 trait object `dyn Trait` 是**胖指针**（数据指针 + vtable 指针，16 字节），把 vptr 放在指针里而不是对象里——同一问题，两种设计取舍。

**验收问题**：为什么"给类加一个虚函数"会让所有同类对象一起变大？

## 例题 1-5 多态 vs 非虚：运行期查表 vs 编译期绑定

**目标**：能用一句话解释"虚调用看对象，非虚调用看指针"。

**代码**：`code/p1_05_polymorphism.cpp`

**真实输出**

```text
&d=0x16b43a460  pb=0x16b43a460  pd=0x16b43a460（单继承下三者地址相同）
-- 虚函数：运行时按对象真实类型查表 --
Derived::speak()
Derived::speak()
-- 非虚函数：编译期按指针类型绑定 --
Base::name()    ← 非虚，看指针的静态类型
Derived::name() ← 非虚，看指针的静态类型
-- 打印两张不同的虚表 --
Base 对象 vptr=0x1049c8068，Derived 对象 vptr=0x1049c8010
speak 槽位：Base=0x1049c4964  Derived=0x1049c48e4
-- 虚析构：用基类指针 delete 必须靠它 --
~Derived()
~Base()
```

**讲解**

1. 单继承下 `pb`（基类指针）和 `pd`（派生类指针）地址相同——**对象只有一个**，区别在"编译器允许你看到多大范围"。
2. `pb->speak()` 仍然调到 `Derived::speak`：因为 `speak` 是虚的，跳转地址来自**对象里的 vptr**。
3. `pb->name()` 调到 `Base::name`：非虚函数在编译期就按 `Base*` 绑定死了。
4. 两张表的 `speak` 槽位地址不同——这就是"多态"的全部机械原理。
5. 最后两行 `~Derived()` → `~Base()`：只有虚析构才能让 `delete 基类指针` 完整析构，否则派生类成员泄漏。

**动手改一改**：删掉 `virtual ~Base()` 后用 `-fsanitize=address` 重跑，观察 ASan 的 leak/不一致报错（这就是第 2 周 D12 的任务）。

**常见误区**：以为"加了 virtual 就是多态"。多态还需要**通过基类指针/引用调用**；用对象本身调用（`d.speak()`）在编译期就能定下来，虚表也可能被优化掉。

**Rust 对照**：Rust 的 `dyn Trait` 只能通过引用/`Box` 调用（对应 C++ 的基类指针），`impl Trait`/泛型则是编译期单态化（对应 C++ 的模板）。

**验收问题**：同一个对象，为什么 `pb->speak()` 和 `pb->name()` 会走到不同的实现？
