# 计划细化版（12 周 · 每天 1 小时）

> 定位不变：**不背概念、不啃厚书、以代码实验为核心**。细化做的是三件事——
> ① 每周切到「当天看得见证据」的粒度；② 每周配可运行例题（见 `code/` 与三份例题讲解）；
> ③ 每周留一个「回到 WebView 项目」的动作，避免学完不知道往哪用。

## 一、每日 1 小时的固定切法

| 时间 | 做什么 | 注意 |
| --- | --- | --- |
| 10 min | 复习昨天结论（凭记忆写三条，不许翻笔记） | 写不出来就说明昨天只是"看过" |
| 35 min | 跑/改当天例题，**先预测再运行** | 预测和实际不符的地方才是今天的收获 |
| 10 min | 记录：结论一句话 + 反例一条 + 存疑一条 | 记到当日笔记，D7 汇总 |
| 5 min | 把当天代码跑一遍 `-fsanitize=address` | 让 ASan 变成习惯，不是排错时才用 |

**每周固定动作（D6–D7）**：把本周例题合成一个小题（自己加一个功能），然后跑 `bash code/run_all.sh asan` 全绿。

## 二、12 周路线图（周目标 + 例题 + 验收）

### 第一阶段：内存地基（第 1–2 周）

| 周 | 主题 | 例题 | 必须能回答的问题 |
| --- | --- | --- | --- |
| 1 | 对象大小 / 对齐 / 栈堆 | `p1_01_sizeof` `p1_02_layout` `p1_03_stack_heap` | 空类为什么是 1 字节？`sizeof` 为什么和成员顺序有关？栈为什么向低地址长？堆上的地址为什么和栈差很远？ |
| 2 | vptr / 虚表 / 多态 | `p1_04_vptr` `p1_05_polymorphism` | 加 `virtual` 对象为什么变大 8 字节？同类对象为什么共用一张表？非虚函数为什么"看指针类型"？ |

**第 1 周细化**

- D1 空类与基础类型：先预测 `Empty/CharInt/IntChar` 的 sizeof，再跑 `p1_01`；关注 `HasFunction`（成员函数不占对象内存）。
- D2 对齐与排布：把 `LooseLayout` 和 `TightLayout` 的成员顺序互换，预测字节数；用 `offsetof` 验证。
- D3 字节可视化：自己写一个 `hexdump(const void*, size_t)`，把成员值手动标到字节序列上。
- D4 栈：在 `level()` 里再加两层递归，画出地址递减的图；解释"栈是复用"的证据。
- D5 堆与释放：把链表改成数组 `new Node[3]`，再改成 `new Node*[3]`，比较三次的地址和释放写法。
- D6 综合小题：写一个 `struct`，同时含 `char/int/double/指针/虚函数`，预测 sizeof 并解释每一字节。
- D7 复盘产出：一页笔记（可打印），三条结论 + 一个反例。

**第 2 周细化**

- D8 `virtual` 的代价：对同一个类加/去 `virtual`，记录 sizeof 变化与 `vtable` 地址。
- D9 vptr 位置：验证 vptr 在对象最前面（把对象首 8 字节当 `void**` 读，并与虚表函数地址对照）。
- D10 简单多态：基类指针指向派生类对象，比较 `pb->speak()` 与 `pb->name()`（虚 vs 非虚）。
- D11 单继承虚表：派生类重写 vs 新增虚函数，观察表槽位是"替换"还是"追加"。
- D12 虚析构：故意去掉 `virtual ~Base()`，用 `-fsanitize=address` 跑一次，看它报什么。
- D13 复盘：口述"对象内存布局 → vptr → 虚调用"的完整链条，写成一个 5 步流程图。
- D14 巩固：把 `p1_05` 改成三个派生类 + 一个工厂函数返回 `unique_ptr<Base>`（提前预热第 6 周）。

### 第二阶段：所有权与资源（第 3–6 周）

| 周 | 主题 | 例题 | 必须能回答的问题 |
| --- | --- | --- | --- |
| 3 | string 底层 | `p2_01_string` | SSO 的边界在哪？为什么 `reserve` 后地址不再变？`size` 和 `capacity` 差在哪？ |
| 4 | vector 底层 | `p2_02_vector` | 扩容倍数与均摊复杂度？什么时候元素被"移动"而不是"拷贝"？迭代器为什么失效？ |
| 5 | RAII | `p2_03_raii` | 为什么异常路径也能释放？为什么禁止拷贝、只允许移动？析构顺序为什么是逆序？ |
| 6 | 智能指针 | `p2_04_unique_ptr` `p2_05_shared_ptr` | move 后源指针为什么变空？循环引用为什么泄漏？`weak_ptr` 凭什么破环？ |

每周的 7 天都按同一模板走：**D1 观察现象 → D2 找出规则 → D3 看底层数据（容量/计数/地址）→ D4 复现一个坑 → D5 对照 Rust → D6 改造例题 → D7 复盘打印**。

本周专属要求：

- 第 3 周：把 `p2_01` 的 SSO 边界从 22 改成"你自己的编译器实测值"，写清依据。
- 第 4 周：给 `Tracked` 去掉 `noexcept` 的移动构造，观察拷贝次数变化——这是"移动语义为什么要求 noexcept"的直接证据。
- 第 5 周：给 `Buffer` 加一个 `swap`，解释为什么移动赋值通常用 swap 实现。
- 第 6 周：把 `p2_05` 的循环引用用 ASan 跑一次，亲眼看它报 leak；再用 `weak_ptr` 修好。

```text

  └─ 派生类（不同算法/不同平台实现）

```

## 三、工具速查（本机命令）

```bash
# 编译（带调试信息、关优化，便于看地址与变量）
clang++ -std=c++17 -g -O0 -Wall p1_04_vptr.cpp -o /tmp/demo

# 内存检查三件套
clang++ -std=c++17 -g -O0 -fsanitize=address demo.cpp -o demo_asan     # 越界/UAF/重复释放
clang++ -std=c++17 -g -O0 -fsanitize=undefined demo.cpp -o demo_ubsan  # 未定义行为
ASAN_OPTIONS=abort_on_error=0 ./demo_asan                              # macOS 上不支持 detect_leaks

# 看符号、看大小、看段
nm -C demo | head            # 列出符号（-C 还原 C++ 名字）
size -m demo                 # 各段大小
otool -l demo | grep -A3 LC_MAIN
c++filt _Znam                # 手写名字还原：operator new[]

# 调试
lldb ./demo                  # b main / r / frame variable / memory read -c 16 &obj
```

## 四、验收标准（每周都问自己）

1. **能预测**：看一段新代码，能先说出 sizeof / 是否泄漏 / 会不会崩，再运行验证。
2. **能复现**：每个结论都能用一个 20 行以内的小程序重现。
3. **能口述**：用"内存/所有权/生命周期"三个词讲清楚，而不是背术语。
4. **能回收**：把结论落回 WebView 项目的一处具体代码（哪怕只是加一个 RAII 守卫）。

## 五、反模式清单（出现就停下来）

- 只看不跑：没有输出的"学习"不算学习。
- 只跑不改：每题的"动手改一改"至少做一条。
- 用 ASan 当排错工具而不是日常习惯。
- 提前钻模板元编程、`constexpr` 细节——12 周计划里它们不是主线。
- 用 `reinterpret_cast` 掩盖类型问题（例题 3-1 会演示它的后果）。
- 记住"结论"却说不出现象：结论必须挂在你亲眼见过的输出上。
